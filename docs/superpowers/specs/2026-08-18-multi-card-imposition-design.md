# 設計: 複数ポップの一括作成と面付け印刷（余白最小化・任意カードサイズ）

- 日付: 2026-08-18
- 対象: 商品ポップメーカー（依存ライブラリなしの素の HTML/CSS/JS・canvas 描画）
- 状態: 承認済み（実装前）
- 前提設計: `2026-08-17-image-and-jis-paper-design.md`

## 1. 背景と目的

現状は「1 ドキュメント = 1 ポップ = 1 用紙」で、`renderer.draw()` が用紙 1 枚ぶんを原点(0,0)に描く。
そのため 44×67mm 程度の小さなポップを A5 などに印刷すると、用紙のほとんどが余白になる。

本改修の目的は次の 3 点。

1. **異なる内容のポップを複数枚**（同一ドキュメント内）作成できるようにする。
   ※「同じポップを複数枚」ではなく、商品ごとに内容が違うカードを並べる。
2. **1 枚のポップ（カード）の大きさを任意の mm で指定**できるようにする（既定 44×67mm）。
3. **印刷時に用紙へ自動で面付け**し、余白を最小化する。入り切らない分は自動で次ページへ。
4. **作ったポップ集を保存して後から呼び出せる**ようにする。印刷したものは自動で残り、
   一覧から選んで作り直し・再印刷ができる。

いずれの処理でも **文字を勝手に縮めない**ことを原則とする。面付けの都合で向きが合わないときは
「縮小」ではなく「回転」で解決する（§4.1・§5）。

## 2. 非目標（YAGNI）

- カードごとに異なるサイズを混在させること（面付けが成立しないため、カードサイズは全カード共通）。
- 用紙サイズの自動選定（「最も無駄が少ない用紙を選ぶ」機能）。枚数表示で人が判断すれば足りる。
- トンボ（コーナートンボ／センタートンボ）や裁ち落とし（ブリード）。家庭用プリンタ＋カッターの用途には過剰。
- CSV 取り込みなどの一括流し込み。カード一覧＋複製で足りる。
- 作品のクラウド同期・共有。保存はこの PC のブラウザ内＋ JSON 書き出しに留める。
- 複数作品の一括書き出し／一括取り込み。必要になってから足す。
- カードの向き切替ボタン（§4.1 の理由により意図的に持たない）。

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| カード (card) | ポップ 1 枚。既定 44×67mm。従来の「用紙」に相当する描画単位 |
| シート (sheet) | 実際に印刷する用紙。A4 など |
| 面付け (imposition) | シート上へカードを格子状に配置すること |
| ドキュメント (doc) | カード配列 ＋ カードサイズ ＋ シート設定 をまとめた保存単位 |

## 4. データモデル（v2）

```js
doc = {
  version: 2,
  activeIndex: 0,

  /* 1枚の大きさ（全カード共通・面付けの前提）。向き切替は持たない＝§4.1 参照 */
  card: { id: 'c44x67', customW: 44, customH: 67 },

  /* 印刷シートと詰め方 */
  sheet: {
    id: 'a4', orientation: 'portrait', customW: 210, customH: 297,
    margin: 5,         // シート端の安全余白(mm) 0〜30
    gap: 0,            // カード同士の間隔(mm) 0〜20
    allowRotate: true, // 90°回転して枚数が増えるなら回転する
    center: true,      // 余った分だけブロックを中央寄せ（枚数は不変）
    cutLine: true      // セル境界にカット線を描く
  },

  /* 各カード。従来の state から paper を除いたものと同型 */
  cards: [ cardState, ... ]   // 1〜100件
}
```

`cardState` は現行 `POPPresets.defaultState()` から `paper` を除いた構造をそのまま使う
（`template` / `catch` / `name` / `price` / `desc` / `note` / `badge` / `image` / `design` / `layout`）。

**設計判断: デザインはカードごとに独立**（全カード共通の共有デザインは持たない）。
理由は、既存の描画エンジン・編集パネル・テンプレート機構がすべて「1 state = 1 カード」を前提に
書かれており、共有／個別に分割すると改修範囲が全域に及ぶため。統一したい場合は
「このカードのデザインを全カードに適用」ボタンで一括反映する（文章系フィールドは対象外）。

### カードサイズのプリセット

| id | ラベル | mm |
| --- | --- | --- |
| `c44x67` | 44×67mm（既定） | 44×67 |
| `meishi` | 名刺（91×55mm） | 91×55 |
| `a8` | A8（52×74mm） | 52×74 |
| `a7` | A7（74×105mm） | 74×105 |
| `b8` | B8・JIS（64×91mm） | 64×91 |
| `sq50` | 正方形（50×50mm） | 50×50 |
| `custom` | カスタム（mm 指定） | 任意 |

### 4.1 カードは向き切替を持たない（縮小を原理的に起こさないため）

**カードには `orientation` を持たせない。** 幅と高さの数値がそのまま寸法になる
（`44 × 67` と入れれば縦長、`67 × 44` と入れれば横長）。

理由は、向き切替ボタンがあると「縦横比が反転するサイズ変更」を 1 クリックで起こせてしまい、
そこで文字が縮む余地が生まれるため。面積が同じなのに `min(67/44, 44/67) = 0.657` 倍に縮むのは
無意味な劣化であり、**縮小の入口自体を無くす**のが最も確実。

印刷時の向きは**面付けが自動で回転**して解決する（§5）。この回転は配置だけを変えるもので、
**カードの中身（文字サイズ・余白・レイアウト）には一切影響しない**。
つまり「A4 に 18 枚並べるためカードを 90° 倒して置く」は起きるが、そのとき文字は縮まない。

`sheet` 側は `orientation`（縦/横）を持つ。用紙の向きはプリンタ設定と対応する実在の概念であり、
かつシートの向きを変えても**カードの中身には影響しない**（面付けの格子が変わるだけ）ため。

### 寸法の解決規則（`cardSize` / `sheetSize`）

既存 `POPPresets.paperSize()` と同じ規則を適用する。

1. `id !== 'custom'` のときはプリセット表の mm を採用し、**`customW/customH` は参照しない**
   （値は保持するだけ。カスタムへ戻したときに復元される）。
2. `id === 'custom'` のときのみ `customW/customH` を採用する。数値でなければ既定値へ丸める。
3. **シートのみ**、`orientation === 'landscape'` なら幅と高さを入れ替える。
   カードにこの手順は無い（4.1）。

### サイズのクランプ（3 つの入口すべてで統一する）

カードは **10mm 以上、かつシート内寸（シート辺 − 余白×2）以下**。この判定を次の 3 か所すべてで走らせる。

| 入口 | 挙動 |
| --- | --- |
| カスタム mm の入力 | 範囲外は丸めて入力欄へ書き戻し、「シートに入る最大は ◯×◯mm です」と通知 |
| カードプリセットの選択 | シート内寸を超えるプリセットは**選べるが警告**を出す（丸めない。シートを変えれば使えるため） |
| シート／余白の変更 | 変更後にカードが入らなくなったら同じ警告を出す |

いずれの場合も配置不能なら `perPage === 0` となり、§8 の警告と書き出しボタンの無効化に接続する。
**カードサイズを黙って書き換えるのはカスタム入力時のみ**とし、それ以外は警告に留める
（プリセットを勝手に変形すると、ユーザーの意図した寸法が失われるため）。

シートサイズは既存 `PAPERS`（JIS A判 / JIS B判 / その他定型 / カスタム）をそのまま流用する。

## 5. 面付け計算（新規 `assets/js/imposition.js`）

DOM に依存しない純関数のみ。Node のテストから直接呼べるようにする。

```js
/* 1方向ぶんの詰め込み数 */
function fit(innerW, innerH, w, h, gap) {
  if (w <= 0 || h <= 0 || innerW < w || innerH < h) return { cols: 0, rows: 0, count: 0 };
  var cols = Math.floor((innerW + gap) / (w + gap));
  var rows = Math.floor((innerH + gap) / (h + gap));
  return { cols: cols, rows: rows, count: cols * rows };
}

/* 回転の有無を比較して有利な方を採る */
function computeLayout(o) {
  var innerW = o.sheetW - o.margin * 2;
  var innerH = o.sheetH - o.margin * 2;
  var a = fit(innerW, innerH, o.cardW, o.cardH, o.gap);
  var b = o.allowRotate ? fit(innerW, innerH, o.cardH, o.cardW, o.gap) : { count: 0 };
  var rotate = b.count > a.count;          // 同数なら回転しない
  var r = rotate ? b : a;
  var cellW = rotate ? o.cardH : o.cardW;  // シート座標での 1 セルの外形
  var cellH = rotate ? o.cardW : o.cardH;
  var usedW = r.cols * cellW + Math.max(0, r.cols - 1) * o.gap;
  var usedH = r.rows * cellH + Math.max(0, r.rows - 1) * o.gap;
  return {
    cols: r.cols, rows: r.rows, perPage: r.count, rotate: rotate,
    cellW: cellW, cellH: cellH, usedW: usedW, usedH: usedH, gap: o.gap,
    originX: o.margin + (o.center ? (innerW - usedW) / 2 : 0),
    originY: o.margin + (o.center ? (innerH - usedH) / 2 : 0)
  };
}

/* ページ内 index → セル矩形（mm・シート左上原点）。layout だけで完結させる */
function cellRect(layout, i) {
  var col = i % layout.cols, row = Math.floor(i / layout.cols);
  return {
    x: layout.originX + col * (layout.cellW + layout.gap),
    y: layout.originY + row * (layout.cellH + layout.gap),
    w: layout.cellW, h: layout.cellH
  };
}

function pageCount(n, perPage) { return perPage > 0 ? Math.max(1, Math.ceil(n / perPage)) : 0; }
```

`perPage === 0`（カードがシートに入らない）のときは描画・印刷を行わず、
「カードがシートより大きいため配置できません」と表示する。このとき `pageCount` は 0 を返し、
シートタブの表示は空（メッセージのみ）、**印刷ボタンとシート PNG 保存ボタンは `disabled`** にする
（カード単体の PNG 保存は有効のまま）。

**仕様上の限界（意図的）**: 回転はグリッド全体に対して一括で決める。行ごとに向きを混ぜる
「棚詰め（shelf packing）」は行わない。混在させれば理論上さらに詰まる組み合わせもあるが、
切り出しの手間が跳ね上がり、カードの向きが揃わないため採用しない。上の期待値表もこの前提。

### 期待値（テストの根拠・カード 44×67mm）

| シート | 余白 5mm（既定） | 余白 0mm |
| --- | --- | --- |
| A4 210×297 | **16枚** 4列×4段・回転なし | **18枚** 3列×6段・回転あり |
| A5 148×210 | **8枚** 2列×4段・回転あり | **9枚** 3列×3段・回転なし |
| A3 297×420 | **36枚** 6列×6段・回転なし | **36枚**（回転しても 4×9=36 で同数） |

## 6. 描画

### 6.1 カード 1 枚（`renderer.js`・変更は最小）

`draw(ctx, state, pxPerMm, assets)` は現行どおり **原点(0,0)にカード 1 枚**を描く。
唯一の変更は用紙寸法の取得元で、`POPPresets.paperSize(state)` → 引数で受け取る
`POPPresets.cardSize(doc.card)` に置き換える。

```js
draw(ctx, cardState, pxPerMm, assets, sizeMm)   // sizeMm = {w,h} を第5引数で受ける
```

後方互換のため `sizeMm` 省略時は `cardState.paper` から従来どおり解決する（v1 データの単体描画用）。

### 6.2 シート合成（新規 `assets/js/sheet-view.js`）

```js
drawSheet(ctx, doc, pageIndex, pxPerMm, assetsByCard, opts)
```

1. シート全体を白で塗る。
2. そのページに載るカードを順に、`ctx.save() → translate → (rotate) → draw() → restore()`。
   - 回転なし: `ctx.translate(rect.x*pxPerMm, rect.y*pxPerMm)`
   - 回転あり: `ctx.translate((rect.x+rect.w)*pxPerMm, rect.y*pxPerMm); ctx.rotate(Math.PI/2)`
     （ローカル +x がシートの下方向、+y がシートの左方向になり、カードの w×h が
     セルの h×w に収まる）
3. `cutLine` が真なら、**全カードを描いた後に**セル境界へ線を重ねる。
   幅 0.2mm・`#b0b0b0` の実線で、**そのページに実際に載っているカードのぶんだけ**引く。
   グリッド全体（`perPage`）ぶん引くと、最終ページの余った部分にまで格子が印刷されてしまうため。
   占有セルの矩形を並べる方法に統一する（ブロックの外周にも線が入る）。
   `gap === 0` のときは隣接カードが境界を共有し同じ線を 2 回なぞるが、不透明な細線なので
   見た目は変わらない。空セルに線を出さないことを優先する。
4. プレビューのみ: 選択中カードの枠をアクセント色でハイライト（**書き出し・印刷には出さない**）。
   `opts.highlightIndex` で制御し、既定は「描かない」。

**前提条件**: `assetsByCard` は呼び出し前に読み込み完了していること（§6.4）。
`drawSheet` 自身は非同期処理を行わず、未ロードの画像は単に描かれない。

**セル背景について**（Fugu レビュー B-1 の検証結果）: `renderer.draw` は
`clearRect(0,0,W,H)` の直後に `design.bg` で同じ矩形を `fillRect` するため、
セル内に透明領域は残らない。したがってシート合成側でセルを事前に白塗りする必要はない。
ただし `gap === 0` で座標が非整数ピクセルに落ちると隣接セルの継ぎ目に細い線が見えうるため、
**シート全体を先に白で塗る**（手順 1）ことで下地を保証する。

### 6.3 画像アセットの準備（`assetsByCard`）

```js
assetsByCard = [ { image: HTMLImageElement|null }, ... ]   // cards と同じ添字
```

既存の `imgCache` を流用し、**カード横断で 1 つのキャッシュ**（`src` をキー）にする。
同じ画像を複数カードで使っても実体は 1 つ。

- **プレビュー**: 現行と同じ「今あるぶんで一旦描画 → ロード完了で再描画」。
  シートタブでは、そのページに載るカードの画像のみを対象にする。
- **印刷・PNG 書き出し**: 対象ページに載る全カードの画像を `Promise.all` で待ってから描画する。
  読み込みに失敗した画像は `null` のまま進み（描画されない）、処理は止めない。
- **一覧サムネイル**: ロード済みの画像のみ使う（待たない）。ロード完了時に §8 の debounce 経由で再描画。

### 6.4 高解像度書き出し

```js
POPSheetView.renderSheetToCanvas(doc, pageIndex, dpi, assetsByCard) → HTMLCanvasElement
```

**`sheet-view.js` に置く**（`drawSheet` を呼ぶため。`renderer.js` に置くと後発モジュールへの
逆依存になる）。A4 300dpi で 2480×3508px。既存の PNG 書き出しと同じく
`toBlob` → `toDataURL` のフォールバックを通す。

## 7. 文字・余白の比例スケール

既存 6 テンプレートは A4（210×297mm）を前提とした数値を持つ（商品名 64pt、`layout.padding` 14mm）。
44mm 幅のカードでは余白だけで 28mm を占め、`autoFit` の二分探索が働いても実用に耐えない。

そこで **スケール係数を状態に焼き込む**方式を採る（描画時に係数を掛けるのではなく、値そのものを書き換える）。
焼き込みなので、適用後にユーザーが個別の数値を手で微調整できる。

```js
/* scale = min(newW/oldW, newH/oldH) */
POPPresets.scaleCard(cardState, scale)
```

| 対象 | スケールする | 丸め・クランプ |
| --- | --- | --- |
| `catch/name/price/desc/note.size`（pt）, `badge.size` | ✅ | 0.1pt 単位・下限 4pt |
| `layout.padding`, `layout.gap`（mm） | ✅ | 0.1mm 単位・下限 0 |
| `image.xMm`, `image.yMm`, `image.wMm` | ✅ | 0.1mm 単位・幅の下限 5mm ＋ 後述のクランプ |
| `design.border.width`（mm） | ✅ | 0.1mm 単位・**下限 0.3mm** |
| `lineHeight`, 色, 文章, `image.opacity/layer/aspect` | ❌ 不変 | — |

`border.width` も比例させる。不変にすると、44mm 幅のカードで A4 用の 1.2mm 枠が相対的に太くなりすぎ、
「テンプレの見た目を相似に保つ」という目的から外れるため。細くなりすぎる方は 0.3mm の下限で受け止める
（300dpi で約 3.5px＝印刷で視認できる）。

画像はスケール後に既存の `app.js:clampImage()` と同じ規則でカード内へ収める
（`wMm` をカード幅以下に、`xMm/yMm` を `0 〜 カード寸法 − 画像寸法` に丸める）。
`clampImage` は現在 `app.js` にありカードサイズに依存するため、`presets.js` 側へ移して共用する。

### 係数の決め方

```js
function scaleFor(oldW, oldH, newW, newH) {
  // 縦横が入れ替わっただけなら拡縮しない（面積が同じなのに縮めるのは無意味）
  if (oldW === newH && oldH === newW) return 1;
  return Math.min(newW / oldW, newH / oldH);
}
```

`min` を使うのは、拡大方向で内容がカードからはみ出さないことを保証するため。
ただし `min` は縦横比が反転すると過小になる（44×67 → 67×44 は面積が同じなのに 0.657 倍）。
§4.1 で向き切替ボタンを廃止したため通常の操作でこの経路には入らないが、
**ユーザーが幅と高さを手入力で入れ替えた場合の保険として、寸法の入れ替えは係数 1 とする**特例を残す。
これ以外の縦横比変化では `min` の保守的な結果を受け入れ、余った余白はユーザーが調整する。

**可逆性（2026-08-19 変更）**: 当初は「変更前→変更後」の比率を現在値へ直接掛ける方式にしたが、
`scaleFor` が `min(...)` である以上**片道でしか働かず、縮めてから戻しても文字が小さいまま**になる。
数値入力欄のスピナーや矢印キーは1段階ごとに確定するため、小刻みな縮小が積み重なる問題もあった。
利用者の「文字を勝手に縮めるな」という要求に照らして受け入れられないため、**基準サイズからの
目標倍率を持つ方式**へ変更する。

```js
doc.scale = { baseW, baseH, applied }   // baseW×baseH のとき applied = 1
POPPresets.scaleStep(doc.scale, newW, newH) -> { delta, target }
// target = scaleFor(baseW, baseH, newW, newH)、delta = target / applied
```

サイズ変更時は `delta` だけを掛け、`applied` を `target` に更新する。これにより
44 → 30 → 44 と戻せば文字も元の大きさに戻る（0.1pt / 0.1mm の丸めぶんの誤差のみ）。

「文字とレイアウトも比例させる」のチェックを外して変更したときは、
「今の見た目がこの大きさに対して正しい」とみなして基準を新しい寸法へ置き直す。

テンプレート適用は基準を置き直さない。テンプレートは常に A4 前提値から現在のカードサイズへ
焼き込むため、結果は他のカードと同じ「現在の大きさに対して正しい値」になり、整合するため。

### 適用タイミング（3 か所）

1. **テンプレート適用時**: テンプレの A4 前提値に `scaleFor(210, 297, cardW, cardH)` を掛けてから `mergeDeep`。
2. **カードサイズ変更時**: `scaleFor(旧W, 旧H, 新W, 新H)` を**全カード**に適用。
   「文字とレイアウトも比例させる」チェックボックス（既定 ON）で無効化できる。
3. **カード新規追加時**: `defaultState()` は A4 前提値のため、
   `scaleFor(210, 297, cardW, cardH)` を掛けてから配列へ追加する。
   「複製」で追加する場合は既にスケール済みのため何もしない。

## 8. 画面（`index.html` / `style.css` / `app.js`）

```
┌ カード一覧 ┐┌──── 編集パネル ────┐┌─[カード]─[シート]─┐
│ ▸1 大福 ¥298││ 商品名 / 価格 / 説明 ││                   │
```

- **カード一覧**: 各行に小さなサムネイル（実描画を縮小）＋商品名＋価格。
  `role="listbox"` / `role="option"`、`↑`/`↓` で選択移動、`Alt+↑`/`Alt+↓` で並べ替え。
  ドラッグ＆ドロップでも並べ替え可（キーボード操作を必ず用意する）。
- **操作**: 「追加（空のカード）」「複製（選択中をコピー）」「削除」。カード上限 100 枚。
  最後の 1 枚は削除不可（削除ボタンを無効化）。
- **プレビューはタブ切替**（横並びは幅が足りない）。既定は「カード」。
  「シート」タブではカードをクリックで選択、ドラッグで並べ替え。
- **カード設定**: 幅・高さの mm 入力とプリセット選択のみ。**縦横の切替ボタンは置かない**（§4.1）。
  シート設定側には用紙の縦/横切替を置く。
- **作品**: ヘッダに「作品を開く」「名前を付けて保存」を置き、
  現在編集中の作品名を常時表示する（未保存なら「未保存」）。
- **常時表示のメタ情報**: 「カード 44×67mm / A4 に 16枚 / 全 3 ページ（カード 40 枚）」。
- **警告表示**:
  - `margin === 0` のとき「フチなし印刷に対応したプリンタ以外では端のカードが欠けます」。
  - `perPage === 0` のとき「カードがシートより大きいため配置できません」。
- **支援技術への通知**: メタ情報と警告は `aria-live="polite"` の領域に置き、
  カード追加・削除・サイズ変更の結果が読み上げられるようにする（既存 `#status` を流用）。
- **サムネイルの再描画コスト**: 100 枚 × 入力のたびに再描画すると重い。
  - 編集中のカードだけを即時更新し、他は据え置く。
  - 全体の再構築は 200ms の debounce。
  - サムネイルは短辺 64px 相当の低解像度で描画し、カードごとに
    「内容のハッシュ（`JSON.stringify` の長さと主要フィールド）」で差分がなければ再描画しない。

## 9. 出力と保存

### 9.1 印刷

シート単位。300dpi でページごとに canvas 化し、iframe へ並べて 1 回の印刷ダイアログで出す。
**印刷を実行する直前に作品ライブラリへ自動記録する**（§9.3）。

```html
<style>
  @page { size: {SW}mm {SH}mm; margin: 0 }
  html,body { margin:0; padding:0 }
  img { width:{SW}mm; height:{SH}mm; display:block; page-break-after:always }
  img:last-child { page-break-after:auto }
</style>
```

**メモリ対策**（Fugu 指摘 D-3）:

- 各ページは `toDataURL` ではなく **`toBlob` ＋ `URL.createObjectURL`** で渡す。
  data URL は base64 で約 1.33 倍に膨らみ、文字列としても保持されるため多ページで不利。
  印刷ダイアログを閉じた後（iframe 破棄時）に `revokeObjectURL` する。
- ページ canvas は 1 枚ずつ生成 → blob 化 → **参照を捨てて次へ**（全ページぶんの canvas を同時に持たない）。
- ページ数が **10 を超える**場合は「◯ページを印刷します。時間とメモリを消費します」と事前確認する。

全ページの画像 `onload`（または `onerror`）を待ってから `print()` を呼ぶ（現行の 1 枚版の待ち合わせを配列化）。

### 9.2 PNG 保存

`export-target` を追加し「シート（面付け済み）」／「選択中カードのみ」を選択。
印刷と同様、書き出しの直前に作品ライブラリへ自動記録する（§9.3）。

シートを選んだときの対象は **既定で「現在表示中のページ」1 枚**（ファイル名 `pop_sheet_2_300dpi.png`）。
「全ページを保存」チェックを別に用意し、有効時のみ複数ファイルを **800ms 間隔で順次**ダウンロードする。

> **理由**（Fugu 指摘 D-1）: 多くのブラウザは連続した自動ダウンロードをブロックし、
> 「複数のファイルのダウンロードを許可しますか？」の確認を出す。既定を 1 枚にすることで
> 通常の操作ではこの確認に当たらない。全ページ保存を選んだときは、その旨を事前に画面へ表示する。

### 9.3 作品ライブラリ（新設）

現行の保存は「作業中の 1 件の自動保存」と「1 カードぶんのデザインのプリセット」しかなく、
**作ったポップ集を後から呼び出して再印刷できない**。ここを作り直す。

#### 保存されるもの

| 種類 | 中身 | 件数 |
| --- | --- | --- |
| **作品（work）** | ドキュメント全体（`cards` 全件 ＋ `card` ＋ `sheet`）＋ 名前・更新日時・サムネイル | 上限 100 件 |
| **作業中（autosave）** | ドキュメント 1 件。起動時に自動復元（現行踏襲） | 1 件 |
| **デザイン型紙（preset）** | 1 カードぶんの見た目のみ（現行のプリセット。名称だけ変更） | 上限 30 件 |

「作品」と「デザイン型紙」は別物として並べる。前者は中身入りのポップ集、後者は見た目の雛形。

```js
work = {
  id: 'w_<連番>_<保存時刻>',   // Date.now() ではなく保存時に採番
  name: '秋の新商品ポップ',
  updatedAt: '2026-08-18T05:30:00.000Z',
  cardCount: 20,
  cardSize: { w: 44, h: 67 },
  thumb: 'data:image/jpeg;base64,...',  // シート1ページ目・長辺160px・q0.7（約8KB）
  doc: { ... }
}
```

#### 印刷・書き出し時の自動記録

「一度作ったものを作り直してまた印刷したい」を成立させるため、
**印刷／PNG 保存を実行すると、その時点のドキュメントが必ず作品として残る**。

- ライブラリ由来のドキュメントを編集中なら → **その作品を上書き更新**（`updatedAt` を更新）。
- どの作品にも紐づいていない新規作業なら → **`無題 2026-08-18 14:30` の名前で新規保存**し、
  以後はその作品に紐づく。保存した旨を `#status` に表示する。
- 保存に失敗しても**印刷・書き出しは続行する**（出力を止めない）。失敗は通知のみ。

#### 一覧 UI

「作品を開く」ボタン → モーダルに一覧（サムネイル・名前・カード枚数・カードサイズ・更新日時）。
新しい順。操作は **開く / 名前を変更 / 複製 / 削除**。削除は確認ダイアログを出す。
上限 100 件に達したら「古い作品を削除してください」と促す（**自動削除はしない**＝
ユーザーの成果物を黙って消さない）。

### 9.4 保存層（`store.js`・新設）

保存先を抽象化し、**IndexedDB を主・`localStorage` をフォールバック**とする。

```js
POPStore.ready()                       // → Promise<'idb' | 'ls' | 'none'>
POPStore.getAutosave() / setAutosave(doc)
POPStore.listWorks() / getWork(id) / putWork(work) / deleteWork(id)
POPStore.listPresets() / putPreset(...) / deletePreset(...)
```

起動時に `indexedDB.open()` を try/catch で試し、成功すれば `'idb'`、失敗すれば `localStorage` を試し、
それも駄目なら `'none'`（保存なしで動作継続・現行と同じく画面に告知）。
**API は 3 経路で同一**なので、呼び出し側はどこに保存されたかを意識しない。

> ⚠ **実装の最初に実機確認する項目**: Chrome は `file://` で開いたページの IndexedDB を
> 拒否する場合がある。本ツールはダブルクリック起動（`file://`）が主な使い方なので、
> ここが `'ls'` に落ちる可能性が高い。**フォールバックが正しく効くことを最初に確かめてから**
> 先へ進む。`http://`（GitHub Pages・ローカルサーバ）で開けば IndexedDB が使える点は
> README に追記する。

#### 容量の見積もりと対策

| 保存先 | 実効容量 | 画像なしカード（約1KB） | 画像付きカード |
| --- | --- | --- | --- |
| `localStorage` | 約 5MB | 約 5000 枚ぶん | 現状の長辺2000px なら **4〜9 点で満杯** |
| IndexedDB | 数百MB〜（空き容量依存） | 実質無制限 | 数百〜数千点 |

**対策 1: 画像の解像度をカードサイズに連動させる**（現行は長辺 2000px 固定）。

```js
maxSide = clamp(Math.round(Math.max(cardW, cardH) * 12), 800, 2000)   // 12px/mm ≒ 300dpi
```

44×67mm なら 800px となり、面積比で **約 1/6**（1 点あたり 530KB〜1.3MB → 80〜200KB）。
300dpi 印刷に必要な画素数は満たすため、画質の実害はない。

トレードオフ: 取り込み後にカードを大きくすると、その画像は解像度不足になる。
カードサイズを拡大したときに画像付きカードがあれば「画像を取り込み直すと鮮明になります」と案内する。

**対策 2: 画像は dataURL のまま持つ**（Blob 化しない）。base64 で約 1.33 倍に膨らむが、
JSON 書き出し・読込・`localStorage` フォールバックのすべてで同じ形が使え、実装が単純になる。
IndexedDB の容量なら 1.33 倍は問題にならない。

**対策 3: 保存失敗時の挙動**（Fugu 指摘 D-2）。
容量超過では **doc 全体の保存が失敗**する（部分保存はしない＝中途半端な状態を復元しないため）。
通知は「カード ◯枚・画像 ◯点のため保存できません。『データ保存』で書き出せます」とし、
セッション中は表示を継続する。保存に失敗しても編集・印刷は続行できる。

### 9.5 JSON 保存 / 読込

ドキュメント全体（`doc`）を保存する。読込時は §10 の移行を通す。
**作品ライブラリのバックアップ・他PCへの持ち出し手段**としての位置づけ
（ブラウザのデータを消すとライブラリも消えるため、この経路は必ず残す）。

- 画像付きカードが増えると JSON が数十 MB に達しうる。
  書き出し前に概算サイズを計算し、**20MB を超える場合は「◯MB になります」と確認**してから続行する。
- 「作品をまとめて書き出す」は今回は作らない（1 作品ずつ）。必要になってから足す。

### プリセット（ブラウザ内保存）

従来どおり **1 カードぶんのデザイン**として扱う。保存＝選択中カード、読込＝選択中カードへ適用。
既存の `popmaker.presets.v1` はそのまま利用できる（`paper` キーがあれば無視する）。

## 10. 移行（v1 → v2）

```js
POPDoc.migrate(data) →
  data.version === 2 && Array.isArray(data.cards) ? normalize(data)
  : v1 の単品 state とみなし
    { version:2, activeIndex:0,
      card:  v1 の paperSize()（orientation 適用後の実寸 w×h）を
             { id:'custom', customW:w, customH:h } として設定,
      sheet: v1 の paper と同一寸法のシート ＋ margin:0, gap:0, allowRotate:false,
             center:true, cutLine:false,
      cards: [ paper を除いた v1 state ] }
```

**シートも v1 の用紙に合わせる**（Fugu 指摘 B-2）。シートを常に A4 既定にすると、
v1 で A5 を使っていたドキュメントが「A4 の中に A5 が 1 枚」という別物の印刷結果になる。
カードサイズ＝シートサイズ・余白 0・カット線なしとすることで、**どの用紙で作った v1 データでも
1 ページに 1 枚・従来とまったく同じ印刷結果**になる。

### `normalize(doc)` の内容

v2 データの読込時（JSON・自動保存の双方）に必ず通す。

1. `cards` が配列でない／空なら、既定カード 1 枚に置き換える。
2. `cards` が 100 件を超えていたら先頭 100 件に切り詰め、切り捨てた件数を通知する。
3. 各カードに `mergeDeep(defaultState(), card)` を掛けて欠損キーを補う（既存の読込と同じ方式）。
4. `activeIndex` を `clamp(0, cards.length - 1)` に丸める（数値でなければ 0）。
5. `card` / `sheet` の欠損キーを既定値で補い、`margin` 0〜30・`gap` 0〜20 にクランプする。

### `activeIndex` の維持（削除・並べ替え時）

- **削除**: 削除後も同じ位置のカードを選ぶ（`clamp(0, length-1)`）。末尾を削除した場合は
  新しい末尾へ移る。最後の 1 枚は削除できない（ボタンを `disabled`）。
- **並べ替え**: 移動したカードを選択したまま追従させる（インデックスを付け替える）。
- **追加・複製**: 新しく増えたカードを選択状態にする。

### 保存先の移行

| 旧 | 新 | 移行 |
| --- | --- | --- |
| `localStorage: popmaker.autosave.v1`（単品 state） | `POPStore` の autosave（doc v2） | 起動時、新側が空なら旧キーを読んで `migrate()` を通す |
| `localStorage: popmaker.presets.v1`（1カードのデザイン30件） | `POPStore` の preset | そのまま読める（`paper` キーがあれば無視）。形は変えない |
| — | `POPStore` の works（新設） | 初回は空。旧データからは作らない |

- **旧キーは削除しない**（元に戻せる余地を残す）。移行後は新側にのみ書き込む。
- IndexedDB が使える環境では、初回起動時に `localStorage` の内容を IndexedDB へ 1 度だけ複写する。
- 不正・破損データは既存同様に握り潰して既定ドキュメントで起動する。
- **起動時のドキュメント決定順**: ① `POPStore` の autosave → ② 旧 `localStorage` の v1 → ③ サンプル
  （初回起動は現行どおりサンプル文言入りのカード 1 枚。カードサイズは 44×67mm）。

## 12. テスト（`test/run.js` に追加・依存なし）

`imposition.js` / `doc.js` / `presets.scaleCard` は DOM に触れないため Node からそのまま読める。

1. `computeLayout` A4・44×67・margin5・gap0 → `cols 4, rows 4, rotate false, perPage 16`
2. 同・margin0 → `cols 3, rows 6, rotate true, perPage 18`
3. A5・margin5 → `rotate true, perPage 8`
4. gap 2mm・A4・margin5 → `perPage 16`（4列: 44×4+2×3=182≤200、4段: 67×4+2×3=274≤287）
5. 同数のときは回転しない（A3・margin5 → `rotate false, perPage 36`）
6. カードがシートより大きい → `perPage 0`
7. `center: true` の `originX/originY` が `margin + (inner - used)/2`
8. `cellRect` の列・行送り（gap 込み）
9. `pageCount(16,16)=1` / `pageCount(17,16)=2` / `pageCount(n,0)=0`
10. `migrate` v1 単品 → cards 1 件・`version 2`・**カードとシートが両方とも旧 paper と一致**・`margin 0`
11. `migrate` v2 → 変化なし（冪等）
12. `scaleCard`: pt が比例・`border.width` も比例（下限 0.3mm）・4pt 下限クランプ・`lineHeight` 不変
13. `scaleFor`: 縦横入れ替えのみ（44×67 → 67×44）は係数 1・それ以外は `min` の値
14. `cardSize` の解決規則（`id` 優先・`custom` のみ `customW/H`・**カードは `orientation` を見ない**）
15. `sheetSize` の解決規則（`landscape` で幅高さを入れ替える）
16. カスタムカードサイズのクランプ（10mm 下限／シート内寸上限）
17. `normalize`: `activeIndex` の範囲外丸め・空 `cards` の補完・101 件目以降の切り詰め・`margin/gap` クランプ
18. 画像の最大辺の算出（44×67mm → 800px・A4 カード → 2000px で頭打ち・下限 800px）
19. 作品の採番と一覧の並び（`updatedAt` 降順・上限 100 件で警告を返す）
20. 自動記録の分岐（作品に紐づく → 上書き／紐づかない → `無題 <日時>` で新規）

既存テスト（折り返し・3 桁区切り・`ptPx`・`mergeDeep`・入力クランプ）は変更せず維持する。

**テストの限界**: canvas 描画（`drawSheet` の回転・カット線）と印刷・ダウンロードの挙動は
Node では検証できない。§14 の受け入れ基準を**ブラウザでの手動確認**で担保する。

## 13. リスクとトレードオフ

- **プリンタの非印字領域**: 余白 0mm はフチなし印刷対応機以外で端のカードが欠ける。既定 5mm ＋ 0mm 時の警告で緩和する。
- **`localStorage` 容量**: カードが増えると自動保存が容量超過しやすい（特に画像付き）。
  既存の「保存できなかった」通知を流用し、カード枚数と画像の有無を含めた文言にする。JSON 保存で退避可能。
- **canvas 面積上限**: A3 × 600dpi のシートは 7016×9933px で上限に達する環境がある。
  既存の `toBlob → toDataURL → 失敗通知` のフォールバックをシート書き出しにも通す。
- **カット線の残り**: 幅 0.2mm の線をセル境界の中心に引くため、切断後に各カードへ 0.1mm 未満が残る可能性がある。
  実用上問題ないと判断し、OFF も可能にする。
- **デザインがカードごと独立**であるため、10 枚のカードの色を変えるには一括適用ボタンを使う必要がある。
  共有デザイン方式より柔軟だが、統一操作は 1 手多い。
- **複数ページ PNG のブラウザ制限**: 全ページ保存は連続ダウンロードの確認ダイアログに当たる。
  既定を「現在のページのみ」にして通常操作では踏まないようにした（§9）。
- **スケールが破壊的**であるため、カードサイズを往復させると丸め誤差ぶん値が減衰する。
  テンプレート再適用で戻せることを画面で案内する（§7）。
- **多ページ印刷のメモリ**: blob URL 化とページ単位の逐次生成で緩和するが、
  A3 × 多数ページでは環境によって失敗しうる。10 ページ超で事前確認を出す（§9.1）。
- **`file://` で IndexedDB が使えない可能性**（最大の未確認事項）: Chrome がこれを拒否すると
  保存容量は `localStorage` の約 5MB に落ちる。画像なしのポップ集なら十分だが、画像を多用すると
  数件で頭打ちになる。フォールバックで機能は壊れないが**容量の期待値が変わる**ため、
  §11 の段階 0 で最初に実測する。回避策は `http://` で開くこと（GitHub Pages / ローカルサーバ）。
- **ブラウザのデータ削除でライブラリが消える**: IndexedDB も `localStorage` もブラウザ側の
  「閲覧データの削除」で消える。恒久的な保管は JSON 書き出し（§9.5）に依存する。
  この点は README とライブラリ画面に明記する。
- **画像の解像度をカードサイズに連動させる副作用**: 小さいカードで取り込んだ画像は、
  後からカードを大きくすると粗くなる。取り込み直しで解決できる旨を案内する（§9.4）。

## 14. 受け入れ基準

> 作品ライブラリ（§9.3・§9.4）に関する項目は別計画で実装する。
> それ以外の項目は実装済みだが、ブラウザでの実機確認は未実施（チェックは人間が実機確認後に付ける）。

- [ ] カードを追加・複製・削除・並べ替えでき、各カードの内容が独立して編集できる
- [ ] カードサイズを 44×67mm（および任意の mm）に設定でき、シート内寸を超える入力はクランプされる
- [ ] A4・余白 5mm で 16 枚、余白 0mm で 18 枚が配置され、画面の枚数表示と一致する
- [ ] カード数が 1 ページを超えると自動で複数ページになり、印刷でページが分かれる
- [ ] 印刷結果が指定どおりの原寸で出る（等倍・余白なし設定時）。定規で 44×67mm を実測して確認する
- [ ] カット線が ON のとき、隣接カードの境界に線が 1 本だけ入り、切ると両カードに残らない
- [ ] 「このカードのデザインを全カードに適用」で見た目だけが揃い、商品名・価格・画像は変わらない
- [ ] PNG を「シート」「選択中カードのみ」の両方で保存できる
- [ ] v1 の JSON／自動保存を読み込むとカード 1 枚として復元され、**A5 など非 A4 で作った v1 も従来と同じ印刷結果**になる
- [ ] カードサイズ変更時に文字・余白が比例し、44×67mm でも初期表示が破綻しない
- [ ] **面付けで回転が起きても、カードの文字サイズ・余白がまったく変わらない**（縮小しない）
- [ ] 印刷すると作品ライブラリに自動記録され、別の作品を作った後で一覧から戻って再印刷できる
- [ ] 作品の改名・複製・削除ができ、削除には確認が出る
- [ ] IndexedDB が使えない環境（`file://` の Chrome 等）でも `localStorage` で同じ操作ができる
- [ ] 保存に失敗しても印刷・PNG 書き出しは完了する
- [ ] `node test/run.js` が全件通る
